onprem-genai-embedded · NASA F´ v4.4.1 · runs 2–3 on Kaggle 2× Tesla T4

A local code model writes unit tests for flight software. The build decides what stays.

Each target is a requirement from NASA's F´ flight-software framework that says it is verified by unit test, yet no test cites it. The agent gathers context from a knowledge graph over MCP, asks a self-hosted model for one GoogleTest case, builds and runs it in F´, repairs from the compiler or assertion output (3 attempts at most), commits passing tests to a review branch, and then seeds bugs to check that the test catches them.

    How many people one 2× T4 server can serve

    IDE chat profile (≈ 2.5k-token prompt, 400-token answer): decode speed each user sees, by number of concurrent streams. Each level uses new prompts.

    At 20 tok/s per user, about 4 concurrent chat users per server with either engine. llama.cpp queues requests past its 4 slots (first token after 71 s at 16 streams); vLLM keeps batching but each user slows to 7 tok/s. Devstral (dense 24B) stays under 20 tok/s even alone.
